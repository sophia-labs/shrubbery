# Panes and appearance — local integrated source

This source adds three small user-facing affordances. A successful local build
does not activate the required Sirin services or release the Tauri host.

## Local-copy explanation

The footer has one compact Local copy button. Its nonmodal popup is anchored
above that button, constrained to the viewport and scrollable. Unknown is a
neutral lack of verification on this device, not a cloud-save failure or a claim
that syncing is in progress. Opening does not mutate or repair anything.
Contested/parked destinations remain explicit actions inside the explanation.
Escape returns focus when the explanation owns it; clicking elsewhere preserves
that new focus. Graph-incarnation/epoch replacement closes stale detail.

## Custom CSS

Open the top bar's Appearance menu, then Custom CSS. The editor is actual Hoja
in its literal source profile: no Markdown or wiki-link transformations. Native
Garden owns one shared stylesheet in the workspace Y.Doc. Browser storage keeps
only approval of an exact hash, scoped by account, graph and incarnation.

Save & apply here changes the shared source with revision/hash/incarnation and
operation-ID guards, then explicitly approves those bytes locally. Apply this
revision here verifies with GET only, so a reader can opt into saved CSS without
writing the graph. Other agents' edits do not silently receive local approval.
Pending writes keep newer drafts; uncertain retries retain the exact operation.
Remote changes or mismatched mutation responses invalidate old consent.

Recovery: Ctrl+Alt+Shift+C disables local CSS and opens the editor. Adding
`?custom-css=off` to the app URL starts in safe mode. Opening the editor suspends
applied CSS. Disable here never changes shared source; Reset shared CSS does.
CSS is limited to65,536 UTF-8 bytes. Global rules reach light DOM, inherited
`--mn-*` variables and exported `::part()` hooks, not arbitrary shadow internals.
CSS syntax is browser-parsed; URL/import requests remain governed by host CSP.

Native's ordinary `custom_css` MCP tool provides guide/read/replace/reset actions.
Its optional expanded read/write schemas use the same authority, guards and
queue. Headless tools cannot claim they inspected computed layout or a screenshot.

## Agent-centered Choreograph and Grapevine

Choreograph's Home is Agents. It reads existing Emporium Agent identities and
their separately attributed body reports using ordinary `agent_status`; `status`
is the separate native publishing tool. A recent report is not independently
verified online presence. Expiry advances locally while the pane is open.
Identity/graph changes reset detail scroll; same-Agent updates preserve reading
position. The initial view is one authorized graph, not an accessible-global
roster. Existing Runs/Monitor remain the runtime evidence entry points.

Grapevine is a real host app region with a Hoja composer, not an iframe. It uses
the exact owner-qualified gateway route and existing sign-in. Configured target
`agentRef` values connect Agent selection to a permitted Zulip channel/topic.
Opening a conversation never sends a message, acknowledges mail or launches an
agent. Zero/multiple mappings remain explicit. Full reload does not preserve
in-memory drafts; uncertain sends retain their exact nonce and require inspection.

A send is confirmed only by the versioned native Zulip message-ID receipt, not
HTTP200 alone. Recipient ACK and Garden archival persistence are separate claims.
Auth readiness, fetch and body decoding share a finite15-second UI settle bound.
Live adoption still requires a selected Zulip realm/audience, linked accounts,
configured conversation targets, matching Grapevine service/gateway route and
reviewed archival access. No live mail is provisioned by this source change.
